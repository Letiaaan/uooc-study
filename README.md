# UOOC Study

**UOOC 本地学习工作台**：选择课程、播放视频、处理独立测验，查看进度与运行记录。支持 UOOC 新旧课程界面、Chrome / Edge、网页 AI 和 DeepSeek API。

默认使用 **网页 AI → 豆包 → 访客 → 自动答题**，无需填写 API Key。千问、DeepSeek 网页需要先在官网登录；程序等待本人完成登录，再继续处理当前测验。

当前版本 **0.4.12**，主要支持 **Windows 10 / 11 x64**。

[隐私政策 / Privacy Policy](PRIVACY.md) · [Code signing policy / 代码签名政策](CODE_SIGNING.md) · [安全报告 / Security Policy](SECURITY.md)

## 已实现的功能

| 功能 | 使用方式与行为 |
| --- | --- |
| 可视化工作台 | 勾选多门课程，查看进度和日志，暂停、继续、停止或退出 |
| 浅色 / 深色主题 | 默认跟随系统，可手动切换；以白、黑和浅蓝为主 |
| 新旧版 UOOC 适配 | 根据可见目录识别版本，匹配章节、知识点与资源标识 |
| Chrome / Edge | 自动选择或手动指定，使用程序专用档案，分别保存登录会话 |
| 视频学习 | 静音、二倍速、定期恢复暂停播放，记录处理位置；完成状态以网站记录为准 |
| 视频弹题 | 单选依次尝试选项，多选尝试非空组合；超过八个选项或特殊交互由本人处理 |
| 独立测验 | 读取整卷文字题，按题号取得答案、校验、填写并提交 |
| 网页 AI | 支持豆包、千问、DeepSeek，每份测验新建会话，自动发送并读取回复 |
| DeepSeek API | 网页 AI 不可用时可由用户手动切换；仅在选用 API 后的测验取答或主动测试连接时调用，启动与正常播放视频不检查密钥 |
| 运行中切换答题方式 | 正在取答的试卷可切换平台或 API；旧回复忽略，填写或提交中的设置从下一卷生效 |
| 登录与验证提示 | AI 登录显示大字提示；UOOC 简单验证自动尝试一次，挑战或失败时等待本人处理 |
| 最终交卷 | 等待官网验证结果就绪，继续点击最终“提交”，观察回执与完成状态 |
| 临时答案管理 | 每卷分别保存、回读并校验；确认通过后只清理该卷答案，失败或结果不明时保留 |
| 异常接管 | 保留原试卷，可继续读取、手动粘贴答案或跳过；关闭已识别的豆包电脑版推广 |

图片题按当前策略处理：可见图片选择题暂选 A，图片填空题留空；其余文字题保留原题号交给 AI。**目前没有图片题识别**，占位答案可能答错。期末、考试类资源与无法识别的交互需本人处理。

## 一、安装与启动

### 直接运行 Windows 程序

1. 从仓库 **Releases** 下载 **`UOOC-Study-complete-windows-x64.zip`（完整包）**。
2. **完整解压**到可写目录，例如 `D:\UOOC-Study`，不要直接在压缩包内运行。
3. 双击 `UOOC-Study.exe` 或 `start.bat`，浏览器会打开本机工作台。

EXE 内置 Node.js 和依赖，**无需另装 Node.js、Python 或模型环境**。首次启动会将运行时解压到 `%LOCALAPPDATA%\UOOC-Study\runtime`，可能需要稍等。

完整包同时包含 `app.js`、`lib/`、`ui/`、`test/`、`tools/`、`.github/`、全部文档、BAT、EXE、完整 `node_modules/` 及官方 Node.js 运行时 `runtime/`。仅排除个人配置、登录数据、构建缓存和历史程序。解压后可直接运行，也可用 `runtime\node.exe app.js` 启动包内源码。

`UOOC-Study-windows-x64.zip` 是较小的运行包，源码和依赖封装在 EXE 内，不展开源码目录；`UOOC-Study-source.zip` 用于源码仓库，不包含运行依赖。需要文件齐全的目录请选择完整包。

程序优先使用本机 Chrome / Edge；两者均不可用时尝试联网下载 Playwright Chromium。建议提前安装 Chrome 或 Edge。

GitHub 的“Code → Download ZIP”下载的是源码，需要按下面的方式运行。作者尚未发布 Release 时，请先使用源码方式。

### 运行源码

安装 [Node.js 24](https://nodejs.org/)，下载源码并解压，在项目目录打开终端：

```powershell
npm ci
npm start
```

也可以双击源码目录的 `start.bat`：它优先使用本机 Node.js 24，必要时安装生产依赖；不满足源码运行条件时尝试调用同目录 EXE。

`npm run check` 只检查本地运行环境，不会登录 UOOC、提交测验或请求 AI。

## 二、第一次使用

### 1. 连接 UOOC

在“课程与任务”填写账号、密码，选择浏览器，点击 **“连接并加载课程”**。

- 表单输入只在本次程序会话使用，不会自动写回配置文件。
- 也可以留空，在程序打开的 UOOC 官网窗口里手动登录。
- 账号已完整填写时，程序尝试一次简单验证；官网确认通过且按钮可用后，自动点击登录一次。
- 图片、滑块挑战、验证失败或账号安全提示需本人处理。**简单验证不保证每次自动通过。**

后续启动会尝试复用所选浏览器的会话；网站可能使其过期，届时需要重新登录。Chrome 与 Edge 使用不同档案，切换浏览器后可能需要分别登录。日常浏览器里的登录不会自动带入程序。

### 2. 确认答题设置

默认是 **网页答题 / 豆包 / 访客 / 自动发送题目并读取回复**。不需要 API Key，可以保持默认。

更换平台时，在“答题设置”选择后点击 **“应用设置”**。未应用的修改只作为表单草稿。

### 3. 勾选课程并运行

| 运行模式 | 适用场景 |
| --- | --- |
| 优先视频，受阻时处理测验 | 优先学习可访问视频；目录受阻时处理已发现的测验，再检查后续目录 |
| 仅查看目录与任务状态 | 检查页面识别、资源与完成状态，不播放或提交测验 |
| 试跑首份独立测验 | **建议首次使用选择**；找到首份未完成的普通测验，尝试一次后停止，不继续第二份 |
| 处理独立测验 | 按章节处理可访问的普通测验，跳过网站已确认完成的项目 |

可勾选多门课程，程序逐门处理。试跑结果不明确或未通过时也会停止，并保留测验页供核对。

### 4. 等待自动取答与提交

```text
读取试卷 → 等待 AI 官网可用 → 新建会话 → 发送整卷文字题
→ 读取完整回复 → 校验题号与答案 → 保存并回读临时文件
→ 填写试卷 → 完成官网验证 → 点击最终提交
→ 网站确认通过 / 完成 → 清理当前试卷临时答案
```

只在官网要求登录、处理协议或验证挑战时需要本人操作。程序检测到页面可用后自动继续，无需手动复制题目，也无需例行点击“继续”。

**验证通过、点击提交和测验通过是不同状态。** 程序会等待交卷结果；未通过或结果不明确时保留原页面及答案，不自动反复重交。

## 三、选择网页 AI 或 API

### 网页 AI

| 平台 | 官网 | 会话要求 |
| --- | --- | --- |
| 豆包 | [doubao.com/chat](https://www.doubao.com/chat/) | 默认访客，也可选官网登录；实际可用性以官网为准 |
| 千问 | [qianwen.com](https://www.qianwen.com/) | **要求先登录**；实测访客固定拒答，登录后可以完成整卷流程 |
| DeepSeek | [chat.deepseek.com](https://chat.deepseek.com/) | **要求先登录**；网页答题不填写模型名或 API Key |

要求登录时，设置区和运行中的工作台顶部会显示大字提示。请在**程序打开的官网窗口**输入账号密码或扫码，在日常浏览器中登录不会带入程序。

“打开并连接官网”用于提前准备页面，自动答题会自行打开官网。登录会话按平台和浏览器保存在本机 `data/ai-profiles/`；访客模式每次连接使用独立档案，不同试卷分别开启新会话。

AI 可能答错、拒答或受到额度限制。程序使用普通网页控件，网站更新可能需要重新适配；服务条件以各平台官网为准。

### DeepSeek API

选择 **DeepSeek API**，填写 [DeepSeek 开放平台](https://platform.deepseek.com/)的 API Key。默认模型 `deepseek-chat`，接口地址 `https://api.deepseek.com`。

点击“应用设置”后使用。**启动时不会自动检查或请求密钥**；只有测验取答或主动点击“测试 API 连接”时请求接口，可能产生费用。测试独立使用当前表单，测试成功后仍需应用设置。

网页聊天与开放平台 API 是两套服务；网页登录不等于取得 API Key，API 方式也不会使用网页账号会话。

### 手动接管与答案格式

自动方式异常时，可展开“网页协作 → 手动接管”，查看整卷提示词、粘贴完整回复、校验并继续，也可跳过本次测验。显式选择手动方式时，才需要复制题目并粘贴回复。

选择题每行一个题号与答案，文字题和填空题使用 JSON 数组：

```text
1.A
2.AC
3.["第一空","第二空"]
```

也兼容 `{"answers":[{"number":1,"values":["A"]}]}`。程序校验题号、数量、选项范围和填空数量，缺题或结构不符时保留待答试卷。结构正确不代表答案内容正确。

## 四、暂停、后台与运行中修改

- **暂停**：视频立即暂停，网页操作在下一个安全节点等待；已发出的网络请求可能继续完成。
- **停止**：关闭本次连接的程序浏览器，结束任务；重新连接可继续处理未完成内容。
- **退出程序**：工作台右上角按钮会停止任务并关闭本地服务。只关闭工作台标签页不会退出程序。
- **后台运行**：可用其他窗口遮挡浏览器。最小化可能停止绘制，操作时程序会恢复窗口并记录提示，不主动切换普通后台标签页。

| 修改内容 | 生效时机 |
| --- | --- |
| 网页 / API、平台、登录方式、自动 / 手动、API 配置 | 正在取答的试卷按新配置重新取答，旧回复忽略；填写或交卷中的试卷从下一次取答生效 |
| 主题、查看日志、复制题目、手动答案校验 | 随时使用 |
| 课程范围、运行模式、UOOC 账号、浏览器、刷新课程、退出账号 | 先停止任务；受限操作会弹窗说明 |

已发送的 API 请求可能仍计费。网页发送结果不确定时只继续读取，不自动重复发送；原会话被关闭时，需要本人找回答案。

## 五、可选配置文件

复制 `config.example.txt` 为同目录 `config.txt`，按需填写。没有配置文件也可通过界面使用。

```ini
USERNAME=
PASSWORD=
BROWSER=auto
ANSWER_PROVIDER=web
WEB_PLATFORM=doubao
WEB_LOGIN=guest
WEB_AUTOMATION=auto
DEEPSEEK_API_KEY=
MODEL=deepseek-chat
BASE_URL=https://api.deepseek.com
```

| 配置项 | 支持值 |
| --- | --- |
| `BROWSER` | `auto` / `chrome` / `msedge` / `chromium` |
| `ANSWER_PROVIDER` | `web` / `api` |
| `WEB_PLATFORM` | `doubao` / `qianwen` / `deepseek` |
| `WEB_LOGIN` | `guest` / `login`；千问、DeepSeek 强制使用登录会话 |
| `WEB_AUTOMATION` | `auto` / `manual` |

显式配置优先于默认值。还支持 `UOOC_USERNAME`、`UOOC_PASSWORD`、`DEEPSEEK_API_KEY` 环境变量，配置文件非空值优先。界面修改只在本次会话生效。

配置与数据保存在程序所在目录。不同账号建议使用不同程序目录，避免共享浏览器档案。

## 六、常见问题

**提示关闭上一个工作台，或 Edge / Chrome 连不上？** 先从旧工作台右上角“退出程序”，再重新连接；同一档案不能由两个工作台同时使用。日常浏览器无需关闭。异常退出后会核对自身记录的端点尝试恢复连接；早期版本留下的无记录窗口可能需手动关闭一次。

**千问或 DeepSeek 看得到输入框，为什么仍等待？** 请在程序打开的那个官网窗口登录。登录、验证和首次使用提示最多等待约 5 分钟；超时后可在原页面处理完成，再继续当前步骤。

**豆包弹出下载广告怎么办？** 程序会关闭已识别的电脑版推广。其他弹窗需本人处理；不会自动下载推广软件或代为接受协议。

**AI 已回复，但程序没有继续？** 查看“网页协作”状态与运行记录。程序等待完整回复并校验题号，拒答、缺题、仍在生成或访问限制都不会作为有效答案。必要时使用手动接管，不要反复发送同一份题目。

**验证通过后还没有交卷？** 程序等待官网回调就绪，再点最终“提交”。查看运行记录中的业务提示；验证成功本身不等于网站接受试卷。结果不明确时保留原卷，不自动重交。

**视频播放完，为什么仍显示待确认？** 完成状态取决于网站进度、课程解锁和学习规则。程序区分播放结束、提交结果待确认和网站确认完成。

**临时答案在哪里，为什么没有删除？** 每卷位于 `data/temp-answers/quiz-*/`，含原回复 `reply.txt`、规范答案 `answers.txt` 和标识 `paper.json`。确认通过后才清理；未通过、结果未知、标识异常或目录多出文件时保留供核对。

## 八、开发、测试与打包

```powershell
npm ci
npm test
npm run check
npm run test:browsers
npm run test:promotions
npm run build:windows
```

- `npm test`：78 项检查，覆盖目录、浏览器、取答、校验、运行控制、交卷、访问控制与清理。
- `test:browsers`：本机 Chrome / Edge 配合豆包 / 千问本地样例，每组两份 30 题试卷，共 8 份；默认不显示窗口，不访问真实课程或 AI 官网。需观察时追加 `-- --headed`。

输出 `dist/UOOC-Study.exe`、`dist/UOOC-Study-complete-windows-x64.zip`（完整包）、`dist/UOOC-Study-windows-x64.zip`（较小运行包）、`dist/UOOC-Study-source.zip`（纯源码）和 `THIRD-PARTY-NOTICES.txt`。完整包包含生产和开发依赖、官方 Node.js 运行时及全部源码文件；源码包按明确清单生成，不包含实际配置、运行数据或构建缓存。根目录同步最新 EXE；旧程序占用时生成 `UOOC-Study-版本号.exe`。

GitHub Actions 会在推送、Pull Request 或手动触发时，在 Windows 上运行自动检查、环境检查和打包。ZIP 在该次 Actions 的 Artifacts 下载；**不会自动发布 Release**。

### 上传 GitHub

推荐仓库名 **`uooc-study`**，显示名称 **UOOC Study**，简介可填写：
